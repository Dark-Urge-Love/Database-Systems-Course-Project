## 三、完整性检查（实测，全部为 0 行）

| 检查项 | 含义 | 异常行数 |
|---|---|---:|
| 号源越界 | `remain_slots` 必须满足 `0 ≤ remain ≤ total` | **0** |
| 号源与预约不一致 | `remain_slots = total_slots − 未取消预约数` | **0** |
| 预约被重复就诊 | `visit.appt_id` 唯一（1-1 联系成立） | **0** |
| 就诊记录挂空预约 | 就诊记录对应的预约状态必须为"已就诊" | **0** |
| 处方单价与药价不符 | `prescription_item.unit_price = drug.price` | **0** |
| 孤立外键（处方） | `prescription.visit_id` 必须存在 | **0** |
| 孤立外键（明细） | `prescription_item.presc_id` 必须存在 | **0** |

> 这一组检查证明了：**外键约束、唯一约束、CHECK 约束全部生效**，且生成的数据在业务逻辑上自洽。

## 六、复现步骤

```bash
# 1. 建库建表（10 张表，含外键/唯一/CHECK 约束）
mysql -h 127.0.0.1 -u root -p < sql/schema.sql

# 2. 生成 22 万条数据（seed 固定，结果可复现）
python sql/data_gen.py --host 127.0.0.1 --user clinic --password Clinic@123456 --seed 2026

# 3. 创建索引（幂等，可重复执行）
mysql -h 127.0.0.1 -u root -p < sql/index.sql

# 4. 校验数据量与完整性
mysql -h 127.0.0.1 -u root -p < sql/verify.sql

# 5. 连通性自检
python tools/check_conn.py --host 127.0.0.1 --user clinic --password Clinic@123456
```
