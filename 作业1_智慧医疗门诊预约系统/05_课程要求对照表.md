## 二、六项基本操作

对应页面：**药房采购工作台 `/ops`**（业务剧本：供应商报价处理）

| # | 课程要求 | 业务环节 | 实际 SQL | 代码位置 |
|---|---|---|---|---|
| 1 | **创建数据表** | 收到供应商报价单，建报价登记表 | `CREATE TABLE drug_quote (...)` | `views.py` → `STEPS["create"]` |
| 2 | **插入数据** | 录入 8 条报价明细；4 种新药批量上架药品目录 | `INSERT INTO drug_quote VALUES (...)`；`INSERT INTO drug SELECT ... WHERE NOT EXISTS` | `STEPS["insert"]` |
| 3 | **修改数据** | 按最新报价调整目录内 4 个品种的价格 | `UPDATE drug d JOIN drug_quote q ON ... SET d.price = q.quote_price` | `STEPS["update"]` |
| 4 | **删除数据** | 试销不达标 / 滞销零库存药品淘汰下架 | `DELETE d FROM drug d LEFT JOIN prescription_item i ... WHERE i.presc_id IS NULL AND (...)` | `STEPS["delete"]` |
| 5 | **删除数据表** | 报价归档，临时报价表完成使命销毁 | `DROP TABLE IF EXISTS drug_quote` | `STEPS["drop"]` |
| 6 | **跨数据表操作（join）** | 药剂科绩效月报（5 表）、客服查患者就诊流水（7 表） | 见下 | `dao.report_doctor_revenue` / `dao.report_patient_flow` |

### join 说明

- **5 表**：`prescription_item → prescription → visit → doctor → department`，分组统计医生开药金额 Top10
- **7 表**：`appointment → patient → schedule → doctor → department → visit → prescription → prescription_item → drug`（含 LEFT JOIN 补全未就诊/未开方记录）

### 演示顺序（页面已内置「▶ 自动演示整个流程」）

① 建表 → ② 插入 → ③ 修改 → ④ 删除 → ⑤ 删表 → 两张报表，全过程约 1 秒，可反复运行。

## 三、三项额外功能

| # | 课程要求 | 实现 | 页面 |
|---|---|---|---|
| 1 | **事务支持** | 挂号：`SELECT ... FOR UPDATE` 锁排班行 + `INSERT appointment` + `UPDATE schedule` 三语句同一事务；任一失败整体 `ROLLBACK`；`CHECK (remain_slots >= 0)` 兜底 | `/register` |
| 2 | **索引支持** | `sql/index.sql` 建 7 个索引（幂等存储过程）；`/perf` 对同一查询对比"走索引"与 `IGNORE INDEX` 全表扫描的 `EXPLAIN` 计划与实测耗时 | `/perf` |
| 3 | **多用户并发访问 + 访问性能记录** | ① `/register` 页「并发抢号」：Barrier 对齐 + 10 线程同时挂号，页面输出成功/失败数、号源变化、总耗时；② `tools/concurrency_test.py` 压测 read/write/mixed 三场景，输出 TPS、P50/P95/P99 到 CSV | `/register`、`tools/` |

### 并发不超卖的原理（可写在报告里）

1. `SELECT ... FOR UPDATE` 对同一 `schedule_id` 行加排他锁，后到的事务阻塞等待；
2. 锁内重新校验 `remain_slots > 0`，把"检查—扣减"放进同一个原子区间；
3. 提交后 `remain_slots` 才释放，因此成功预约数恒等于号源减少数，不可能为负。

## 五、答辩演示脚本（约 3 分钟）

1. **首页 `/`**：指出课程要求 → 功能的对照表，同时看到 10 表 22 万行、服务器主机名与 Linux 数据目录（证明数据在服务器上）
2. **`/ops`**：点「自动演示整个流程」，逐张卡片讲业务动机与 SQL（六项基本操作全在这一条业务链上）
3. **`/ops` 报表区**：生成 5 表与 7 表 JOIN 报表，说明跨表操作
4. **`/register`**：提交一次挂号，看号源 N → N−1 与事务 SQL
5. **`/register` 并发区**：10 线程抢号，看"成功数 = 号源减少数"，无超卖
6. **`/perf`**：对比 `type: ALL` 与 `ref`、扫描行数几万 → 个位数、耗时对比

## 六、与"被删除功能"的说明

为保证聚焦课程要求，以下内容已移除（原设计中的扩展，非课程要求）：

- 医生接诊 / 开处方页面（`/clinic`）及其事务、药品查询、药品库存扣减、缴费流水写入
- 首页的预约状态分布、科室排行、药品消耗排行（join 已由 `/ops` 报表覆盖）
- 索引的"真删 / 重建"对照功能（改为 `IGNORE INDEX` 绕过索引，不修改库结构）

数据库表结构与 22 万条数据不受影响——处方、缴费等数据仍由 `data_gen.py` 生成并用于 join 报表。
