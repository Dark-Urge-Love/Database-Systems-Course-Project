## 二、六项基本操作

对应页面：**数据管理台 `/ops`** —— 全部由用户亲自操作，不是预置脚本。

| # | 课程要求 | 用户怎么操作 | 实际 SQL | 后端接口 |
|---|---|---|---|---|
| 1 | **创建数据表** | 填写表名与字段（名称 / 类型 / 是否必填），点「创建表」 | `CREATE TABLE 表名 (id INT AUTO_INCREMENT PRIMARY KEY, 字段 类型, ...)` | `/api/crud/create_table` |
| 2 | **插入数据** | 选中任意表 → 点「插入数据」→ 按字段逐项填写 → 保存 | `INSERT INTO 表 (列...) VALUES (%s...)`（参数化） | `/api/crud/insert` |
| 3 | **修改数据** | 点某行「改」→ 表单回填 → 修改后保存（如药品调价） | `UPDATE 表 SET 列=%s... WHERE 主键=%s` | `/api/crud/update` |
| 4 | **删除数据** | 点某行「删」→ 确认删除 | `DELETE FROM 表 WHERE 主键=%s` | `/api/crud/delete` |
| 5 | **删除数据表** | 在「我创建的表」里点「删表」→ 二次确认 | `DROP TABLE 表名` | `/api/crud/drop_table` |
| 6 | **跨数据表操作** | 底部报表区一键生成 | 5 表 / 7 表 JOIN（见下） | `/api/report` |

### 可操作的表

- **业务表**：`drug`（药品目录，可入库新药 / 调价 / 下架）、`patient`（患者档案，可建档 / 改联系方式 / 注销）
- **自建表**：用户通过页面创建的任意表，可增删改查并在不需要时删表
- **保护规则**：10 张核心业务表不可 DROP；删除被外键引用的行会返回友好提示（如"该记录正被其他表引用（外键约束保护），不能删除"）

### JOIN 报表

- **5 表**：`prescription_item → prescription → visit → doctor → department`，医生开药金额 Top10
- **7 表**：`appointment → patient → schedule → doctor → department → visit → prescription_item → drug`，某患者完整就诊流水

### 安全设计（报告可提）

表名 / 列名经正则白名单校验后反引号包裹（标识符无法参数化），值全部 `%s` 参数化传入，从根上防 SQL 注入；常见 MySQL 错误码翻译成人话提示（外键 1451、唯一冲突 1062、日期格式 1292 等）。

### 演示建议顺序（约 2 分钟）

1. 建一张 `supplier` 供应商表（表单现场填字段）
2. 选中 `supplier` 插入 2 行数据
3. 选中 `drug` 插入一种新药，然后点「改」调价
4. 删掉刚才的测试行；再点一条被处方引用的药，看外键保护提示
5. 删掉 `supplier` 表
6. 底部生成两张 JOIN 报表

## 三、三项额外功能

| # | 课程要求 | 实现 | 页面 |
|---|---|---|---|
| 1 | **事务支持** | 挂号：`SELECT ... FOR UPDATE` 锁排班行 + `INSERT appointment` + `UPDATE schedule` 三语句同一事务；任一失败整体 `ROLLBACK`；`CHECK (remain_slots >= 0)` 兜底 | `/register` |
| 2 | **索引支持** | `sql/index.sql` 建 7 个索引（幂等存储过程）；`/perf` 对同一查询对比"走索引"与 `IGNORE INDEX` 全表扫描的 `EXPLAIN` 计划与实测耗时 | `/perf` |
| 3 | **多用户并发访问 + 访问性能记录** | ① `/register` 页「并发抢号」：Barrier 对齐 + 10 线程同时挂号，页面输出成功/失败数、号源变化、总耗时；② `tools/concurrency_test.py` 压测 read/write/mixed 三场景，输出 TPS、P50/P95/P99 到 CSV | `/register`、`tools/` |

### 并发不超卖的原理（可写在报告里）

1. `SELECT ... FOR UPDATE` 对同一 `schedule_id` 行加排他锁，后到的事务阻塞等待；
2. 锁内重新校验 `remain_slots > 0`，把"检查—扣减"放进同一个原子区间；
3. 提交后 `remain_slots` 才释放，因此成功预约数恒等于号源减少数，不可能为负。

## 五、答辩演示脚本（约 3 分钟）

1. **首页 `/`**：指出课程要求 → 功能的对照表，同时看到 10 表 22 万行、服务器主机名与 Linux 数据目录（证明数据在服务器上）
2. **`/ops`**：现场操作——表单建表 → 插入数据 → 修改调价 → 删除行 → 删表，每步下方都有实际执行的 SQL
3. **`/ops` 报表区**：生成 5 表与 7 表 JOIN 报表，说明跨表操作
4. **`/register`**：提交一次挂号，看号源 N → N−1 与事务 SQL
5. **`/register` 并发区**：10 线程抢号，看"成功数 = 号源减少数"，无超卖
6. **`/perf`**：对比 `type: ALL` 与 `ref`、扫描行数几万 → 个位数、耗时对比

## 六、与"被删除功能"的说明

为保证聚焦课程要求，以下内容已移除（原设计中的扩展，非课程要求）：

- 医生接诊 / 开处方页面（`/clinic`）及其事务、药品查询、药品库存扣减、缴费流水写入
- 首页的预约状态分布、科室排行、药品消耗排行（join 已由 `/ops` 报表覆盖）
- 索引的"真删 / 重建"对照功能（改为 `IGNORE INDEX` 绕过索引，且只忽略真实存在的索引，不修改库结构）
- 预置剧本按钮（最初版本），全部改为用户亲自操作的表单

数据库表结构与 22 万条数据不受影响——处方、缴费等数据仍由 `data_gen.py` 生成并用于 join 报表。
