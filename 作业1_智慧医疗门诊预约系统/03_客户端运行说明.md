# 客户端运行说明

> 智慧医疗 · 社区门诊预约与处方管理系统 —— 作业 1 的 B/S 客户端部分
> 结构：浏览器（Windows） → Flask 客户端（Windows） → TCP/IP → MySQL 8.0（Ubuntu 服务器）

---

## 一、目录结构

```
作业1_智慧医疗门诊预约系统/
├── 启动客户端.bat              ← 双击这个就能启动（推荐）
├── run.py                      ← 启动入口
├── requirements.txt            ← 依赖清单
├── .venv/                      ← 项目自带的虚拟环境（已装好依赖）
│
├── webapp/                     ← 客户端程序（分层设计）
│   ├── config.py               配置：数据库地址、端口
│   ├── db.py                   连接与事务底层（transaction 上下文管理器）
│   ├── dao.py                  所有 SQL 语句（数据访问层）
│   ├── services.py             业务事务：挂号 / 药房发药与并发发药演示
│   ├── views.py                页面路由与 Ajax 接口
│   ├── netprobe.py             自动发现 Linux 服务器地址
│   ├── templates/              Jinja2 页面模板（4 个页面）
│   └── static/style.css        样式表
│
├── tools/
│   ├── concurrency_test.py     多客户端并发性能测试（标志性实践 4）
│   └── check_conn.py           数据库连通性自检
│
├── sql/                        建表 / 索引 / 数据生成 / 校验脚本
└── deploy/                     Linux 部署脚本
```

**分层的好处**（报告里可以直接讲）：`views` 只负责页面与参数校验，`services` 只负责业务规则和事务边界，
`dao` 只负责 SQL，`db` 只负责连接与提交回滚。改 SQL 不动页面，改页面不动事务。

## 二、怎么启动

### 步骤 1：先让服务器跑起来

打开开始菜单里的 **Ubuntu** 图标（就是那台 Linux 服务器）。
程序已经配置好：**只要打开 Ubuntu，MySQL 会自动启动**，不需要敲任何命令。

想确认的话，在 Ubuntu 窗口里敲：

```bash
dbstatus          # 显示：MySQL 运行中 · 192.168.x.x:3306
```

> 如果显示未运行，敲 `dbup` 手动启动。

### 步骤 2：启动客户端

双击项目根目录下的 **`启动客户端.bat`**。
它会自动打开浏览器到 `http://127.0.0.1:5000`。

命令行方式（等价）：

```bat
cd /d "D:\lyl coding\大三上\数据库课设\作业1_智慧医疗门诊预约系统"
.venv\Scripts\python.exe run.py
```

关闭那个黑色窗口就是停止服务。

## 三、页面与功能的对应关系

| 页面 | 地址 | 演示了什么 | 对应课程要求 |
|---|---|---|---|
| 数据概览 | `/` | 数据规模、课程要求入口、各表行数、连接信息 | 数据量（10 表 22 万行）、要求覆盖情况 |
| 药房业务 | `/ops` | 药品目录：新药入库 / 调价 / 停用删除；药品台账：新建台账（建表，自动挂 drug_id 外键）、按药品登记（插入）、删除台账（删表）；运营报表：5/6/7 表 JOIN + 台账关联药品；并发发药：多窗口同时发同一种药，验证不超发并逐次记录响应耗时 | 六项基本操作、多用户并发 |
| 挂号 | `/register` | 挂号事务：扣号源 + 生成预约同事务完成 | 事务 |
| 索引对比 | `/perf` | EXPLAIN 执行计划 + 实测耗时对比 | 索引支持 |

### 建议的演示顺序（答辩时照这个走）

1. **`/` 首页** —— 先讲课程要求怎么一一对应到功能，同时证明数据真的在服务器上（看"服务器主机名""数据目录"两栏），共 22 万+ 行
2. **`/ops` 药房业务** —— 现场演示：① 新药入库 ② 编辑调价 ③ 删除录错的药品（再试一条已开方或在台账登记过的药，看业务拦截）④ 新建「药品不良反应登记」台账（四类模板一键带出字段，建表 SQL 自动带 drug_id 外键）⑤ 按药品登记一条台账记录 ⑥ 删除该台账 ⑦ 生成四张运营报表（重点看"药品消耗排行"和"药品台账总览"）
3. **`/register` 挂号** —— 选科室 → 医生 → 排班 → 患者，提交，看号源从 N 变 N−1（事务）
4. **`/ops` 并发发药** —— 把库存重置为 5，让 10 个药房窗口同时发同一种药：成功 5、失败 5、库存 5→0，发出数量与成功次数一致（多用户并发）；每次访问的耗时同时写入访问日志表
5. **`/perf` 索引对比** —— 看 EXPLAIN 的 type 从 ALL 变成 ref、rows 从几万变成个位数

## 四、服务器地址是自动找的

Ubuntu（WSL）每次重启后虚拟网卡 IP 会变，所以客户端启动时会自己找服务器：

1. 先读 `wsl_ip.txt`（Ubuntu 启动时自动写出，最准）
2. 再读上次成功连接过的缓存 `.db_host_cache`
3. 都没有就**扫描 WSL 虚拟网卡所在网段**，找开放 3306 端口的主机
4. 每个候选地址都用真实账号登录验证，并且检查 `@@datadir` 是不是 Linux 路径 —— 
   这样即使本机也装了账号相同的 MySQL，也不会连错

> 想手动锁定地址不让它自动探测：
> `set DB_HOST=192.168.x.x && python run.py`

## 五、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面顶部红点"数据库未连接" | Ubuntu 没在运行 | 打开开始菜单里的 Ubuntu |
| 同上 | Ubuntu 在跑但 MySQL 没起 | 在 Ubuntu 里敲 `dbup` |
| 页面提示"暂时连不上数据库服务器" | 地址变了 | 刷新页面，程序会自动重新扫描（约 2 秒） |
| 端口 5000 被占用 | 已有实例在跑 | 关掉之前的黑窗口，或改 `webapp/config.py` 里的 `WEB_PORT` |
| 中文显示乱码 | Windows 终端编码 | 本项目只影响终端输出，网页里是 utf8mb4，正常 |

## 六、并发性能测试（单独的压测工具）

在项目根目录执行：

```bat
.venv\Scripts\python.exe tools\concurrency_test.py --clients 20 --duration 15
```

参数：

- `--clients` 并发客户端数（默认 20）
- `--duration` 持续秒数（默认 15）
- `--scenario read|write|mixed` 场景（默认 mixed，读写 7:3）

它会输出总数、成功率、TPS、平均/P50/P95/P99/最大响应时间，按秒采样画柱状图，
并把明细 CSV 和汇总 CSV 写到 `tools/` 目录（汇总表可以直接在 Excel 里画 TPS 折线图）。

压测会临时插入一条"号源充足"的测试排班，**结束后自动删除**，不会污染业务数据。
