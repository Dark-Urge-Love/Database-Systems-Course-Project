# 客户端运行说明

> 药品进销存管理系统 —— 作业 1 的 B/S 客户端部分
> 结构：浏览器（Windows） → Flask 客户端（Windows） → TCP/IP → MySQL 8.0（Linux 服务器）

---

## 一、目录结构

```
作业1_药品进销存系统/
├── 启动客户端.bat              ← 双击这个就能启动（推荐）
├── run.py                      ← 启动入口
├── requirements.txt            ← 依赖清单（Flask + PyMySQL）
├── .venv/                      ← 项目自带的虚拟环境（已装好依赖）
│
├── webapp/                     ← 客户端程序（分层设计）
│   ├── config.py               配置：数据库地址、端口、账号
│   ├── db.py                   连接与事务底层（transaction 上下文管理器）
│   ├── dao.py                  所有 SQL 语句（数据访问层，4 张 JOIN 报表）
│   ├── services.py             业务事务：采购入库 / 销售出库 / 并发出库
│   ├── views.py                页面路由 + Ajax 接口 + 动态业务表单
│   ├── netprobe.py             自动发现 Linux 服务器地址
│   ├── templates/              Jinja2 模板（3 个页面）
│   └── static/style.css        手写样式表
│
├── tools/
│   ├── check_conn.py           数据库连通性自检（端口/登录/库表/join）
│   ├── selfcheck_req.py        课程要求逐条实测（数据库层，13 项）
│   ├── selfcheck_api.py        接口层自检（39 项）
│   ├── concurrency_test.py      多客户端并发压测（read/write/mixed）
│   ├── model_gen.py            建模文件 → DDL/ER 图 生成器（含 --verify）
│   └── render_er.py            Mermaid → PNG（Chrome headless）
│
├── sql/                        建模文件 / 建表 / 索引 / 数据生成 / 校验
└── deploy/                     Linux 部署与开机自启脚本
```

**分层的好处**（报告里可以直接讲）：`views` 只负责页面与参数校验，`services` 只负责业务规则和事务边界，
`dao` 只负责 SQL，`db` 只负责连接与提交回滚。改 SQL 不动页面，改页面不动事务。

## 二、怎么启动

### 步骤 1：先让服务器跑起来

打开开始菜单里的 **Ubuntu** 图标（那台 Linux 服务器）。
项目已配置好开机自启：**只要打开 Ubuntu，MySQL 会自动启动**，不需要敲任何命令。

想确认的话，在 Ubuntu 窗口里敲：

```bash
dbstatus          # 显示：MySQL 运行中 · 192.168.x.x:3306
```

> 如果显示未运行，敲 `dbup` 手动启动。

### 步骤 2：启动客户端

双击项目根目录下的 **`启动客户端.bat`**，它会自动打开浏览器到 `http://127.0.0.1:5000`。

命令行方式（等价）：

```bat
cd /d "D:\lyl coding\大三上\数据库课设\作业1_药品进销存系统"
.venv\Scripts\python.exe run.py
```

关闭那个黑色窗口就是停止服务。

## 三、页面与功能的对应关系

| 页面 | 地址 | 演示了什么 | 对应课程要求 |
|---|---|---|---|
| 数据概览 | `/` | 数据总量、数据表数、库存结存、近效期批次；各表行数；服务器信息（主机名 / 版本 / 数据目录） | 数据量（13 表 15.3 万行）、要求覆盖情况 |
| 进销存业务 | `/ops` | 5 个页签：药品目录（增/改/删）、采购入库·销售出库（6 表事务）、业务表单（建表/插入/删表）、运营报表（4~7 表 JOIN）、并发出库（10 终端不超卖 + 访问性能日志） | 六项基本操作、事务、多用户并发 |
| 索引对比 | `/perf` | 同一查询"走索引 / `IGNORE INDEX`"的 `EXPLAIN` 执行计划 + 实测耗时对比 | 索引支持 |

### 页签内各区域说明

| 页签 | 区域 | 内容 |
|---|---|---|
| 药品目录 | 列表 + 表单 | 药品编码/名称/规格/分类/厂家/采购价/零售价/是否处方药；支持按名称或编码搜索；删除时会检查是否已被采购/销售引用（有则拦截，提示改为"停用"） |
| 采购入库·销售出库 | 左侧入库表单 | 选供应商 / 仓库 / 采购员 / 药品 → 填数量、单价、批号、生产日期、有效期 → 一次提交完成"采购单 + 明细 + 批次 + 库存 + 流水"6 表事务 |
| | 右侧出库表单 | 选仓库 / 销售员 / 药品 / 客户类型 → 填数量 → 近效期先出、过期批次自动跳过；库存不足直接拒绝 |
| | 下方两张流水表 | 最近采购（4 表 JOIN）、最近销售（5 表 JOIN） |
| 业务表单 | 四类模板 | 药品召回登记 / 库存盘点差异 / 药品调价记录 / 冷链温控记录；选模板 → 一键带出字段 → 建表（`bizform_xxx`，自动挂 `drug_id` 外键）→ 按药品登记记录 → 删表（二次确认，提示将删除 N 条） |
| 运营报表 | 四张报表 | ① 供应商供货排行（5 表）② 药品销售排行（5 表）③ 效期预警批次溯源（6 表）④ 单品流向追溯（7 表） |
| 并发出库 | 并发面板 | 指定药品 + 仓库 + 客户端数 + 初始库存 → 10 个线程同时出库 → 输出成功/失败数、库存变化、总耗时、平均/最快/最慢、吞吐量，并显示 `access_log` 最近 12 条 |

### 建议的演示顺序（答辩时照这个走，约 3 分钟）

1. **`/` 数据概览** —— 先讲课程要求怎么一一对应到功能，同时证明数据真的在服务器上（看"服务器主机名""数据目录"两栏），共 15.3 万行
2. **`/ops` 药品目录** —— ① 新增一个药品 ② 编辑调价 ③ 删除它（再试一条已被采购引用的药，看业务拦截）④ 同名同规格再次新增，看"目录中已有该品种"提示
3. **`/ops` 采购入库** —— 给刚建的药品做一次入库，填批号与效期；提交后库存与批次同时出现（6 表事务），下方"最近采购"能看到这条单
4. **`/ops` 销售出库** —— 出库 5 件，看库存从 N 变 N−5、流水新增一条负数记录；再把数量填成"库存+100"，看库存不足拦截
5. **`/ops` 业务表单** —— 新建「药品召回登记」→ 选一种药登记一条 → 删除该表单（建表 / 插入 / 删表）
6. **`/ops` 运营报表** —— 生成四张报表，重点讲 6 表"效期预警批次溯源"与 7 表"单品流向追溯"
7. **`/ops` 并发出库** —— 库存重置为 8，10 个终端同时出库：成功 8、失败 2、库存 8→0，`oversold=false`；访问日志同步新增 10 条
8. **`/perf` 索引对比** —— 看 `type` 从 `ALL` 变 `range`、`rows` 从 5.7 万变几百、耗时 8.6 ms → 0.6 ms

## 四、连的是哪台数据库？（两套配置，自动选择）

Linux（WSL2）每次重启后虚拟网卡 IP 会变，而且服务器账号（`druguser`）与
本机 MySQL 的账号（`root`）并不是同一套，所以客户端启动时按下面的顺序自动找：

| 顺序 | 目标 | 判定方式 |
|---|---|---|
| 1 | `wsl_ip.txt`（Ubuntu 启动时写出的 IP） | 用 `druguser` 登录成功 + `@@datadir` 为 Linux 路径 |
| 2 | `.db_host_cache`（上次成功过的地址） | 同上 |
| 3 | `config.SERVER_HOST`（默认 `192.168.150.181`） | 同上 |
| 4 | 扫描 WSL / Hyper-V 虚拟网卡所在网段（约 2 秒） | 同上 |
| 5 | **本机 MySQL `127.0.0.1`（回退）** | 用 `root` 登录成功即认为可用 |

- 前 4 步成功 → 页面标注 **"课程环境：Linux 服务器"**，`数据目录` 显示 `/var/lib/mysql/`
- 只有第 5 步成功 → 页面标注 **"开发模式：本机 MySQL"**，`数据目录` 显示 `D:\MySQL\...`，
  并在顶部给出提示：课程要求的正式环境是 Linux 服务器，请在 Ubuntu 里执行
  `deploy/init_server_db.sh` 补齐 `druguser` 账号与 `drug_db` 数据

> **答辩前请确认页面标记为"课程环境：Linux 服务器"**，否则会被认为数据没部署到 Linux 上。

想手动锁定目标（不做任何探测与回退）：

```bat
:: 锁定 Linux 服务器
set DB_HOST=192.168.x.x && .venv\Scripts\python.exe run.py

:: 只认 Linux 服务器，连不上直接报错（不偷偷用本机库）
set ALLOW_LOCAL_FALLBACK=0 && .venv\Scripts\python.exe run.py
```

> 两个缓存文件（`wsl_ip.txt`、`.db_host_cache`）都是运行期产物，已在 `.gitignore` 中排除；
> IP 变了或换机器时可以直接删掉，客户端会重新探测。

## 五、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面顶部红点"数据库未连接" | Ubuntu 没在运行，且本机 MySQL 也没起 | 打开 Ubuntu；或启动本机 MySQL 后刷新 |
| 同上 | Ubuntu 在跑但 MySQL 没起 | 在 Ubuntu 里敲 `dbup` |
| 提示"暂时连不上数据库服务器" | 地址变了 | 刷新页面，程序会自动重新扫描（约 2 秒） |
| 页面提示"当前连接的是本机 MySQL" | 服务器上还没有 `druguser` 账号或 `drug_db` 数据 | 在 Ubuntu 里 `bash deploy/init_server_db.sh`，重启客户端即可自动切回服务器 |
| 命令行报 `1045 Access denied for user 'druguser'` | 服务器上没这个账号（换系统后最常见） | 同上 |
| 端口 5000 被占用 | 已有实例在跑 | 关掉之前的黑窗口，或改 `webapp/config.py` 的 `WEB_PORT` |
| 提示"库存不足：该仓库只剩 N 盒" | 出库数量超过结存 | 减少数量，或先做一次采购入库 |
| 提示"该记录正被其他业务引用，不能删除" | 外键 RESTRICT（错误码 1451） | 改为"停用"，或先清理引用它的单据 |
| 提示"库存不能为负数" | CHECK 约束（错误码 3819） | 检查出库数量与初始库存 |
| 中文显示乱码 | Windows 终端编码 | 只影响终端输出，网页是 utf8mb4，正常 |

## 七、并发性能测试（单独的压测工具）

在项目根目录执行：

```bat
.venv\Scripts\python.exe tools\concurrency_test.py --clients 10 --duration 6 --scenario mixed
```

参数：

- `--clients` 并发客户端数（默认 20）
- `--duration` 持续秒数（默认 15）
- `--scenario read|write|mixed` 场景（默认 mixed，读写 7:3）
- `--host/--user/--password/--db` 连接参数（默认自动探测，账号 `druguser` / `drug_db`）

输出总数、成功率、TPS、平均/P50/P95/P99/最大响应时间，按秒采样画柱状图，并把明细 CSV 与汇总 CSV 写到
`tools/` 目录（汇总表可直接在 Excel 里画 TPS 折线图）。

压测会临时选一条库存充足的 `(药品, 仓库)` 做写入，**结束后自动把库存恢复原值**并清理 `ref_no='BENCH'`
的测试流水，不污染业务数据。

**实测（10 客户端 × 6 秒）**：read 496.2 TPS / write 184.2 TPS / mixed 545.2 TPS，成功率均 100%。
